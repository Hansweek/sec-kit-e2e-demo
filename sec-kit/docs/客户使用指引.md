# 研发安全流水线 · GitHub 使用指引（客户版）v2

> 适用：已交付 `sec-kit/`（bin/ 扫描脚本）+ `security-scan.yml`（GitHub Actions 工作流）的客户仓库。
>
> **v2 更新（2026-10-12）**：① SAST 报告升级为**详情报告**并归档**全缺陷+全跟踪路径**（JSON/HTML）；
> ② SCA 扫描后自动导出 **SBOM(SPDX 2.3)+VEX(CSAF 2.0)** 一并归档；③ **项目自动纳管**——项目经理=令牌归属人、
> 归属部门=令牌归属人部门、仓库协作人自动加入项目成员；④ SAST 与 SCA **并行执行**缩短流水线时间；
> ⑤ 钉钉**聚合卡片**（一条消息汇总 SAST+SCA+SBOM，支持加签）。已接入 v1 的仓库换 `bin/` 与 yml 即升级。
> 你只需要完成"一、接入配置"一次，之后日常**无需任何操作**——提 PR 自动扫描，钉钉自动通知。
>
> **阿里云效 Flow 仓库**：接入方式不同——薄封装为 `ci/yunxiao/yunxiao-security-step.sh`（流水线"自定义 Shell"步骤执行），
> 界面配置见交付包 `ci/yunxiao/云效Flow接入指南.md`。核心脚本、能力（增量/门禁/通知/报告）与变量契约与本指引完全一致；
> SAST 项目维度归属在云效侧对应变量 `SAST_PROJECT_NAME`（作用同本指引 §一.5 的 `SAST_PROJECT_NAME`）。
> 本指引的门禁开关（§四）、排障思路（§五）、安全说明（附）两边通用。

## 一、接入配置（管理员，一次性，约 30 分钟）

### 1. 前提确认（2 分钟）

- 仓库 → Settings → Actions → Runners：能看到 runner 且状态为 **Idle（绿点）**
- 手里有：CodeAI 平台地址+个人访问令牌、SCA 平台地址(带 :30001 端口)+用户令牌、钉钉机器人 Webhook

### 2. 放置文件（5 分钟）

把交付包里的两样东西放进仓库（可直接提交，**里面没有任何密钥**）：

| 文件 | 放置位置 |
|---|---|
| `sec-kit/` 整个目录 | 仓库根目录 |
| `security-scan.yml` | `.github/workflows/security-scan.yml` |

**必须合入默认分支**（main）——tag 触发和每日定时只认默认分支上的工作流文件。

> runner 有自定义 label 时，改 `security-scan.yml` 里 `runs-on:` 那行（三种写法已注释在文件里，三选一）。

### 3. 配置 Variables（Settings → Secrets and variables → Actions → Variables）

**必填 3 项**：

| Name | 值 |
|---|---|
| `SAST_URL` | CodeAI 平台地址（结尾不带 /） |
| `SAST_USERNAME` | SAST_TOKEN 归属人的平台用户名（个人中心可见）——用于自动设置项目经理/归属部门 |
| `SCA_URL` | SCA 平台地址（**必须带 :30001 端口**） |

推荐补充：`SCA_USERNAME`（SCA 令牌归属人用户名；不配时继承 `SAST_USERNAME`——两边同名账号时只需配一个）。

可选（不配即用安全默认值）：`SAST_PROJECT_ID`（直连已有项目）、`SAST_GATE_SUPER/HIGH/MIDDLE/LOW`（门禁阈值）、
`SAST_TIMEOUT_MINUTES`(默认60)、`SCA_TIMEOUT_MINUTES`(默认60)、`DINGTALK_AT`(需@的手机号)、
`SBOM_TYPES`(默认 `spdx vex`；可加 `cyclonedx` 同时导出多格式)、`TLS_INSECURE`(自签证书平台配1)

嵌入式仓库额外配：`ENABLE_SCA_ARTIFACT=1`、`SCAN_PATTERNS`（固件产物正则，如 `.*\.(bin|hex|img|tar\.gz)$`）、`SCA_ARTIFACT_DIR`（产物目录，可空）——**拿到固件样本前先不配**，不影响依赖扫描。

### 4. 配置 Secrets（同页 Secrets 标签，必填 3 项）

| Name | 值 |
|---|---|
| `SAST_TOKEN` | CodeAI 右上角头像→个人中心→访问令牌 |
| `SCA_USER_TOKEN` | SCA 个人中心→访问令牌 |
| `NOTIFY_WEBHOOK` | 钉钉群机器人 Webhook（推荐；**加签/关键词模式均可**） |
| `NOTIFY_SECRET`（可选） | 钉钉机器人"加签"密钥——v2 聚合通知已支持加签，机器人可任选安全模式 |
| `GH_MEMBER_TOKEN`（可选） | 只读 PAT——仓库协作者接口被组织策略限制时的成员同步兜底（不配则用 GITHUB_TOKEN 自动拉取） |

> 旧变量 `DINGTALK_WEBHOOK` 仍兼容（未配 NOTIFY_WEBHOOK 时自动使用）。
> 令牌只存 GitHub Secrets（日志自动打码、不进代码仓库），配置后无需再管。

### 5. 项目自动纳管 v2（默认开启，零配置生效）

**v2 起项目维度归属全自动**，规则如下（CodeAI 与 SCA 行为一致）：

| 平台要素 | 自动取值 |
|---|---|
| 项目名 | = 仓库名（无需配置；多仓归一项目时才配 `SAST_PROJECT_NAME`/`SCA_PROJECT_NAME`） |
| 项目经理 | = 令牌归属人（按 `SAST_USERNAME`/`SCA_USERNAME` 解析） |
| 归属部门 | = 令牌归属人所在部门（平台组织架构同步，无需手工指定） |
| 项目成员 | = 仓库协作人（流水线自动拉取 GitHub collaborators 并按用户名匹配平台账号；未匹配的记入日志提醒） |

要点：

- 平台无同名项目时**自动创建**（带上述归属信息）；已有同名项目直接复用
- 需要关闭自动创建配 `SAST_PROJECT_AUTO_CREATE=0`；直连已有项目配 `SAST_PROJECT_ID`（数字，优先级最高）
- 协作人匹配前提：平台存在**同名账号**（如 GitHub login `xin.wang` = CodeAI/SCA 用户名 `xin.wang`）。新同事入职在平台建同名账号后，下次扫描自动纳入（SCA 支持存量项目同步成员，配流水线变量 `SCA_PROJECT_SYNC_MEMBERS=1`；CodeAI 成员在项目创建时生效，存量项目加人走平台 UI）
- 项目归属不影响增量基线（应用按 `仓库名-分支名` 复用，版本对比延续）

## 二、首次验证（30 分钟，照做即通）

1. **提一个测试 PR**（随便改一行代码）→ 仓库 Actions 页出现 `security-scan` 流水线（sast 与 sca 并行）→ 等它跑绿 → 该次运行的 **Artifacts → security-reports** 里应有：
   - `sast_report.pdf`（详情报告）
   - `sec-results/sast-defects-full.json / .html`（全缺陷+全跟踪路径）
   - `sec-results/sbom_*.spdx.json`（SPDX 2.3 SBOM）与 `vex_*.csaf.json`（VEX）
   - `sec-results/【应用报告】*.xlsx`（SCA 检测报告）
2. **钉钉群收到一条聚合卡片**：引用块三行核心数据（缺陷四色合计、漏洞四色合计、组件/许可证基础数据），正文为各检测分段与报告直达链接；门禁未启用时结论显示"检出摘要（门禁未启用）"，只有门禁开启后才出现"通过/未通过"
3. **验证增量**：再改一行代码提一个 PR → 点开 CodeAI 扫描步骤日志，应出现"**存在变更文件 → 增量扫描**"（只扫变更文件，速度显著加快）
4. **平台核对**：登录 CodeAI/SCA 平台，项目管理中出现以仓库名命名的项目，项目经理=令牌归属人、部门=归属人部门、成员=仓库协作人；应用以 `仓库名-分支名` 命名归入项目

到这里接入完成。以下都是自动发生的。

## 三、日常使用（研发人员零操作）

| 行为 | 自动发生的事 |
|---|---|
| 开发提 PR / PR 有新提交 | CodeAI 源码扫描（增量）+ SCA 组件依赖扫描 → 钉钉通知 → 归档报告 |
| 代码合入 main | 同上（合并后全量基线更新） |
| 打 tag 发版（如 v1.2.0） | 全量扫描 |
| 每天 09:30（北京时间） | 自动全量巡检默认分支（改 yml 里的 cron 可调整时间） |

## 四、开关体系（管理员操作）

### 4.1 扫描执行开关（要不要跑扫描）

| 变量 | 作用 |
|---|---|
| `ENABLE_SAST=0` | 关闭 CodeAI 源码扫描（不配 = 执行） |
| `ENABLE_SCA=0` | 关闭 SCA 扫描（依赖+制品一起关；不配 = 执行） |

默认两个都跑。临时停某一路扫描（如引擎维护窗口）：配 0 后下次流水线生效，删除变量即恢复。扫描开关与门禁开关互不影响。

### 4.2 质量门禁开关（扫了要不要阻断，两级模型）

**先理解再操作**：门禁=缺陷数超过阈值时流水线置红（阻断）。灰度期默认**全部只告警**（钉钉照样报数，但不拦人）。

| 开关 | 作用域 | 说明 |
|---|---|---|
| `SECURITY_GATE` | org 级或仓库级 | **总开关**：置 1 一键打开所有仓库的所有门禁，置 0/删除一键关闭 |
| `SAST_GATE_ENABLED` | 仓库级 | 组件覆盖：设 0/1 时**优先于总开关**，只管 CodeAI 门禁 |
| `SCA_DEPS_GATE` | 仓库级 | 同上，只管 SCA 依赖红线 |
| `SCA_ARTIFACT_GATE` | 仓库级 | 同上，只管 SCA 制品红线 |

**⚠ 开闸必须同时配阈值**：门禁按"缺陷数 > 阈值"判断，阈值全 0 = 任何缺陷即阻断（零容忍）。推荐路径：

1. 试运行 1–2 周（全关，只看钉钉告警里的缺陷统计）
2. 配阈值：`SAST_GATE_SUPER=0`、`SAST_GATE_HIGH=0`（超危/高危零容忍）、中低危按业务放宽（如 `SAST_GATE_MIDDLE=10`）
3. 试运行仓库先单独开 `SAST_GATE_ENABLED=1` 观察
4. 稳定后 org 级 `SECURITY_GATE=1` 全面开闸

## 五、排障：手动验证与常见问题速查

### 5.1 手动验证（CI 失败时先做这一步，5 分钟定位问题域）

在 runner 机器（或任一能访问两个平台地址的机器）上执行：

```bash
export SAST_URL=<填 SAST_URL 的值> SAST_TOKEN=<填 SAST_TOKEN 的值>
export SCA_URL=<填 SCA_URL 的值> SCA_USER_TOKEN=<填 SCA_USER_TOKEN 的值> DEPS_GATE=0
bash sec-kit/bin/codeai-incremental-scan.sh     # 日志应出现"任务提交成功"并等待结果
bash sec-kit/bin/sca-scan.sh provision && source ./provision.env && bash sec-kit/bin/sca-scan.sh deps
```

判断标准：

- **两条都成功** → 脚本与平台链路正常，问题在 GitHub 侧配置：检查 Secrets/Variables 名称拼写、`runs-on` 与 runner 标签是否匹配、yml 是否已合入默认分支
- **手动也失败** → 按日志报错对照下方速查表；解决不了把两条命令的完整输出发悬镜支持

注意：令牌只放临时环境变量，验证完执行 `unset SAST_TOKEN SCA_USER_TOKEN`，不要写进任何文件。

### 5.2 常见问题速查

| 现象 | 含义 | 处理 |
|---|---|---|
| 日志报"请设置 SCA_PROJECT_TOKEN" | 没按交付版 yml 跑（缺 provision 步骤） | 用交付的 yml 原文，不要删 provision 两行 |
| 返回码 101104 | 同一应用上次任务还在排队/检测中 | 正常，流水线会自动等待其结果 |
| 返回码 101103 | 引擎并发超限（License 5 并发） | 错峰重试；高频团队可联系悬镜评估扩容 |
| 日志反复出现 5003 | 任务未就绪 | 正常，自动继续轮询 |
| 每次都是全量、没有"增量扫描" | 上一任务未完成（基线 hash 完成后才回写）或克隆不完整 | 等上一任务完成再提交；确认 yml 里 `fetch-depth: 0` 未删 |
| 排队超 60 分钟被放行 | 共享引擎排队（BY_PASS 保护） | 正常，钉钉有放行通知，结果稍后在平台查看 |
| 钉钉收不到 | 机器人非关键词模式 / 关键词不匹配 | 机器人用"自定义关键词"模式，关键词含 `扫描`、`检测` |
| PR 突然全部变红 | 门禁开关被打开而阈值未配 | 检查 `SECURITY_GATE`/组件开关，配阈值或先关闸 |
| 日志提示"协作人无同名用户" | 平台缺该 git 用户的同名账号 | 在平台用户管理建同名账号；SCA 侧配 `SCA_PROJECT_SYNC_MEMBERS=1` 后下次自动补入 |
| VEX 文件里 vulnerabilities 为空 | 应用漏洞尚未审计（VEX=处置结论声明，未审计=空清单属正常语义） | 随平台侧漏洞审计推进自动丰富；漏洞明细看结果页/Excel 报告 |
| 协作人拉取提示 403 | 组织限制 GITHUB_TOKEN 读成员接口 | 配 `GH_MEMBER_TOKEN`（只读 PAT）或变量 `PROJECT_MEMBERS` 手工清单 |

**什么时候找悬镜**：日志出现退出码 2（脚本/平台错误）、平台任务状态异常（4/5/9）、需要扩容并发——提供流水线日志最后 50 行即可定位。

## 附：安全说明（给安全部门）

- 扫描代码流向：GitHub runner（客户内网机器）checkout → 打包 → 上传至客户自己的 CodeAI/SCA 平台，**源码不出企业域**
- 令牌只存 GitHub Secrets（AES 加密、日志自动 masked），不进代码仓库、不落 runner 磁盘
- 扫描脚本为只读分析，不修改代码、不执行仓库内容
